# Архитектура 7day

## Принципы

1. **Offline-first.** Будильник обязан срабатывать без интернета. Источник
   истины — локальное хранилище устройства (AsyncStorage через Zustand
   `persist`). Supabase — дополнительный слой (бэкап, синхронизация, соц-функции),
   а не зависимость для базовой работы.
2. **Логика отделена от UI.** Вся доменная логика — чистые функции в
   `src/features/*/logic.ts`, покрытые unit-тестами. Экраны и сторы — тонкий
   слой сверху. Это даёт быстрые тесты без эмулятора и переиспользование логики
   на бэкенде (Edge Functions).
3. **Типобезопасность.** Общие типы в `src/types`, строгий TS (`strict: true`).

## Слои

```
Экраны (app/**)          — Expo Router, презентация, навигация
  │  читают/пишут
Сторы (src/store/**)     — Zustand + persist(AsyncStorage)
  │  вызывают
Логика (src/features/**) — чистые функции (тестируемые)
  │  и
Инфраструктура (src/lib) — notifications, supabase, storage, i18n
```

### Управление состоянием

Три независимых стора, каждый персистится под своим ключом:

- `alarmStore` — будильники + история пробуждений; при каждом изменении
  перепланирует локальные уведомления (`reschedule`).
- `waterStore` — профиль, записи о воде, настройки напоминаний.
- `breathingStore` — профиль отказа от курения, лог тяги, счётчик сессий.

`partialize` гарантирует, что персистятся только данные, а не функции.

## Модуль 1: Будильник — надёжность

### Кросс-платформенный слой (реализован)

`src/lib/notifications.ts` планирует локальные уведомления через
`expo-notifications`:

- Повторяющийся будильник → по одному weekly-триггеру на каждый выбранный день.
- Разовый → daily-триггер, отключаемый после срабатывания.
- Канал Android `alarms` имеет `importance: MAX`, `bypassDnd`, кастомную
  вибрацию и публичную видимость на локскрине.

При тапе по уведомлению `app/_layout.tsx` направляет пользователя на
`app/alarm/ring.tsx`, где миссия блокирует снус до выполнения.

### Нативный апгрейд для Android (Фаза 1.5, план)

JS-запланированное уведомление — best-effort: агрессивные OEM-оптимизации
(Xiaomi/MIUI, Huawei, Samsung) могут задержать или убить его. Для гарантии
«будильник нельзя пропустить» добавляем нативный слой через `expo prebuild` +
config-plugin:

- `AlarmManager.setAlarmClock()` — точное срабатывание, исключение из Doze.
- **Full-screen intent** (`USE_FULL_SCREEN_INTENT`) — экран будильника поверх
  локскрина, как у системного будильника.
- **Foreground service** на время звонка — предотвращает убийство процесса.
- Разрешение `SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM` (Android 13+) уже
  заявлено в `app.json`.
- Гайд пользователю по отключению battery-optimization для приложения.

На iOS уведомления надёжны системно; критичен приоритет канала и звук.

## Модуль 1: Миссии

`src/features/missions/logic.ts` — чистая логика:

- **Математика** — `generateMathSet(difficulty)` даёт 2–3 примера возрастающей
  сложности; проверка ответа локальная.
- **Аффирмация** — `affirmationMatches()` — толерантное сравнение по доле
  совпавших слов (речь-в-текст неточен). Нормализация регистра, пунктуации, ё/е.
  Распознавание речи подключается нативно (`@react-native-voice/voice`) после
  prebuild; логика сверки уже готова и протестирована.
- **Шаги** — `expo-sensors` Pedometer, счётчик до цели (`MissionRunner`).
- **Фото** — `expo-camera` захват; опциональная AI-проверка объекта через
  Claude vision — Фаза 2.

## Модуль 1: Fajr

`src/features/alarm/fajr.ts` — компактная реализация алгоритма PrayTimes без
зависимостей: солнечная позиция (склонение + уравнение времени) → часовой угол
для угла погружения солнца (по умолчанию 18°, Muslim World League) → локальное
время Fajr в минутах. Точность ~1 мин, покрыто тестом для Ташкента.

## Модуль 4: Вода

`dailyGoalMl()` — норма 35 мл/кг с коэффициентами активности и жаркого климата
(актуально для ташкентского лета), с клампом 1.5–5 л. Напоминания —
`scheduleWaterReminders(interval)` в заданном окне дня.

## Модуль 5: Дыхание

Паттерны техник заданы данными (`pattern: BreathStep[]`), поэтому анимированный
гайд (расширение/сжатие круга) управляется прямо из данных. SOS-режим логирует
триггер тяги, запускает box breathing и при завершении помечает тягу
«побеждённой» → питает статистику `quitStats()` (дни без курения, не выкурено
сигарет, сэкономлено сум). `premium: true` гейтит продвинутые техники.

**Позиционирование:** обязательный дисклеймер в UI; никаких заявлений о лечении.

## Модуль 3: AI-питание (Фаза 2, схема готова)

Поток: фото еды → Supabase Edge Function → **Claude API (vision)** с image input
→ структурированный ответ (блюдо, граммовка, ккал, БЖУ) → пользователь может
скорректировать → запись в `meal_entries`. Ключ Anthropic хранится только на
сервере (Edge Function), не в бандле.

Локальная БД продуктов (`foods`) с приоритетом узбекской/региональной кухни —
глобальные базы её не покрывают. Полнотекстовый индекс для ручного поиска-fallback.

## Backend: Supabase

`supabase/migrations/0001_init.sql` — таблицы всех модулей и **RLS** (owner-only
по `auth.uid()`; `foods` — public-read). Триггер `handle_new_user` создаёт
профиль при регистрации. Клиент (`src/lib/supabase.ts`) опционален: при
отсутствии env-переменных приложение работает локально.

## Тестирование

Unit-тесты (`__tests__/`) покрывают всю чистую логику: генерацию/проверку
математики, fuzzy-сверку аффирмаций, streak, `nextOccurrence`, норму воды,
статистику отказа от курения, расчёт Fajr. Запуск: `npm test` (Jest, jest-expo).

## Что осознанно НЕ входит в этот scaffold

- Нативные модули (alarm/full-screen intent, STT) — требуют `prebuild`.
- Реальные ассеты иконок/сплэша (в `assets/` — плейсхолдер).
- Экраны фитнеса и AI-питания (Фазы 2–3) — схема БД заложена.
- Платёжная интеграция (Payme/Click) — Фаза монетизации.
